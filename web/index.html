Guide

          
GenSys-LTL decides whether a controller can win a logical LTL game, and computes the winning region by symbolic fixpoints over Z3 formulas.

        

        

      

      

        
How it runs

        
Everything runs on your machine. The page loads Python (Pyodide) and the Z3 solver as WebAssembly, and runs the GenSys-LTL engine from this repository. Nothing is sent to a server. Z3 is single-threaded in the browser, so runs are slower than the native tool; use Stop or a time limit for heavy benchmarks.

        
Writing a specification

        
A specification is a Python script. It defines the state variables through the parameters of the environment function (x is the current value, x_ the next one), a list of controller moves, a guarantee, and initial states, then calls a fixpoint procedure. The encoding picked above is passed as sys.argv[1], which the benchmarks use to choose a procedure.

        
Simple games

        
safety_fixedpoint_gensys(controller_moves, environment, guarantee, mode, game_type, init)       # G(φ)
reachability_fixedpoint_gensys(controller_moves, environment, guarantee, mode, game_type, init) # F(φ)
buchi_fixedpoint_gensys(controller_moves, environment, guarantee, mode, game_type, init)        # GF(φ)
cobuchi_fixedpoint_gensys(controller_moves, environment, guarantee, mode, game_type, init)      # FG(φ)

        
game_type is "Int", "Real" or "Bool". mode is always 0 (the controller plays first). An init of False computes the maximal winning region.

        
Product games

        
For an LTL formula with a deterministic Büchi or co-Büchi automaton, encode the automaton as a Z3 relation over q, q_ and the state variables:

        
buchi_fixedpoint(controller_moves, environment, guarantee, mode, automaton, isFinal, nQ, game_type, init)
cobuchi_fixedpoint(controller_moves, environment, guarantee, mode, automaton, isFinal, nQ, game_type, init)

        
General LTL

        
When no deterministic automaton exists, the on-the-fly determinization procedure bounds the automaton counters by K. sigma partitions the automaton's predicates.

        
otfd_fixedpoint(controller_moves, environment, guarantee, mode, automaton, isFinal, sigma, nQ, K, game_type, init)
otfd_fixedpoint_nonsigma(controller_moves, environment, guarantee, mode, automaton, isFinal, sigma, nQ, K, game_type, init)

        
Automata are currently written by hand from the output of Spot. The benchmarks show complete encodings.

        
Exit codes used by the benchmarks

        
5: the chosen encoding does not apply to this benchmark. 6: the encoding is known not to scale and was not written.
